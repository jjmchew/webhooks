# Webhooks mini project

- I had just been exposed to the idea of webhooks and wanted to better understand how they worked.
- I also wanted to play around with generating dynamic sub-domains and using them as part of the app.
- This project also allowed me to do that and play around with deployment and VPS setup.

**Caveats**:

- This project is not production-ready - there is no API security
- No process manager (e.g., `systemd`) was configured to manage the back-end server
- This project does not have a complete dev environment (e.g., for testing sub-domains, etc.)

## Objectives

- Create a crude version of "request bin" (<https://pipedream.com/requestbin>)
- Deploy a mini React project to a VPS which uses:

  - postgres (docker)
  - mongo db (docker)
  - react front end

- Get custom subdomains working as part of the bin URL

## Setup

- VPS setup:
  - recommend using a VPS with at least 2 GB RAM to accommodate postgres / mongo db images
  - install docker-cli (<https://docs.docker.com/engine/install/ubuntu/#install-using-the-repository>)
  - install NGINX (<https://www.digitalocean.com/community/tutorials/how-to-install-nginx-on-ubuntu-22-04>)
  - install node (v20+) (e.g., via NVM):
    - `curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash`
    - `nvm install v20.11.0`
  - for desired domain, ensure a DNS A record for \* also directs to the VPS IP address
  - clone this repo to the VPS
    - Create a `.env` in both `/front` and `/back` based on `env.example` in each folder (including the desired domain name)
    - `npm i` in both `/front` and `/back`
    - in `/front`: run `npm run build` to build the front end and deploy to desired folder on VPS
    - in `/back`: run `npm run prod` to run the back-end server at PORT 3000
  - for SSL certificates (to enable HTTPS):
    - follow instructions to install certbot: `https://certbot.eff.org/instructions?ws=nginx&os=snap`
    - run `/config/getcert.sh [base domain name]` to get SSL certificates
    - follow instructions to add the required DNS TXT record for SSL validation when prompted by certbot
  - copy `/config/default` to VPS `/etc/nginx/sites-available/` (over-writing the existing `default` file)

### June 1, 2024 notes

- the project now roughly works using "custom" sub-domains generated by the app
- summary:
  - a requestbin project
  - binNames are generated by the app and the back-end receives requests sent to the bin (using a subdomain URL)
  - managing the flow of http traffic through nginx and within express was the trick
    - learned that 301 redirects can change the http method to 'get', now using a 308 redirect in nginx
    - learned that nginx is probably better to conduct initial traffic flow, rather than sending all traffic to express
    - express can serve static files with an incorrect content-type header which created issues with firefox
    - for future learning, get more comfortable with nginx configs

### Nov 16, 2025 notes

- noticed that GET requests to the users "bin" are not captured (these requests get handled by the React SPA)
- nginx config for server blocks must be specifically defined to serve the SPA or reverse proxy for the appropriate domains / sub-domains
  - the updated `default` nginx config in `/config` more specifically addresses each type of request
  - also, needed to ensure the back-end did not serve static files (SPA) for "root" paths (e.g., GET requests to `https://https://1585-f1de-d788.example.com`). Otherwise, these GET requests to sub-domain "bins" will not be captured in the bin.
